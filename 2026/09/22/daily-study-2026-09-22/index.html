🔧 嵌入式知识：离散 PID、anti-windup 与 bumpless transfer

工程问题：给输出加 clamp 后，解除限幅为什么仍冲到另一端

平台分两层：主机 C11 数值实验模拟一阶对象，目标为 STM32F407 1 kHz 固定周期控制环。CMSIS-DSP 提供高效 PID 递推，但官方 PID 文档定义的是特定增量实现，不自动包含执行器限幅、anti-windup、模式切换和微分滤波。本文给出显式状态实现，便于审计。

位置式控制器采用微分作用于测量，避免设定值阶跃产生 derivative kick：

Kaw*(u-u_raw) 是 back-calculation：饱和时把实际输出与请求输出的差拉回积分器。Kaw 太小恢复慢，太大可能引入噪声/离散振荡。执行器的速率限制、下游电流限制也必须反馈“实际施加输出”，只对最终 amplitude clamp 回算仍会遗漏其他饱和。

采样周期是参数的一部分

连续域 Ki、Kd 离散后包含 Ts。把 1 kHz 参数直接放到 100 Hz，会让每步积分增加十倍时间却若错误省略 Ts 得到完全不同控制器。实际调度抖动小且有界时可使用固定系数；若动态 dt，滤波与积分都要一致更新，并重新分析稳定性。

微分对高频测量噪声敏感。上式一阶滤波 alpha=exp(-2πfcTs)；fc 太低增加相位滞后，太高放大噪声。设定值预滤波、微分作用于测量和两自由度 PID 是不同设计，不应用“平滑”一个词混淆。

可运行主机数值实验

下面完整 C 程序模拟 y_dot=(-y+u)/tau，输出限制 ±1。第 2 秒设定值跳到 2（不可达），第 5 秒回到 0.5。把 kaw 改为 0 即可复现 windup。编译：cc -std=c11 -O2 pid_sim.c -lm && ./a.out > trace.csv。

通过脚本比较 kaw=0 与 kaw=8：前者在不可达设定期间 I 持续增长，设定回落后输出仍长时间卡在上限；后者 I 被拉回并较快恢复。数值结果不是调参证明，只验证实现机制。

条件积分与 back-calculation 的区别

条件积分在输出已达上限且误差还推动更高时停止积分；若误差推动离开饱和则允许。它参数少，但面对速率限制、级联内环饱和和复杂执行器时不如 tracking 明确。back-calculation 使用实际输出，能统一多种限制，却增加 Kaw 动态。

不能简单“饱和时全部停积分”：若积分方向正在帮助退出饱和，冻结会延迟恢复。MathWorks 的官方 anti-windup 说明也区分 back-calculation、clamping 和 tracking，并强调执行器上下限进入控制器模型。

嵌入式实现与故障守门

下面单精度实现加入 amplitude 与 slew limit，并把实际输出用于回算。调用者保证固定 Ts；传感器无效、NaN 或 dt 违规时不应调用正常 step，而进入安全状态。

固定点实现还需证明乘加位宽、Q 格式、舍入和饱和顺序。CMSIS Q15/Q31 PID 的状态与系数布局必须按官方函数契约，不能在外部 clamp 后假定内部状态已 anti-windup。浮点也要处理 NaN：普通比较对 NaN 为假，手写 clamp 可能让 NaN 穿透执行器。

bumpless manual/auto 切换

手动模式输出 u_manual 时，PID 内部状态若冻结，切回自动的 P+I+D 与当前执行器不等，产生跳变。tracking 做法是在手动期间更新积分：

切换前还要令 y_prev=y 或预置微分滤波状态，避免历史测量制造 D kick。在线改 Kp/Kd 也需重算 I 保持当前输出。MathWorks 的 bumpless transfer 官方示例用 tracking mode 表达同一目标。

状态机应明确：DISABLED 输出安全值并清/跟踪；MANUAL 跟踪实际输出；AUTO 正常控制；FAULT 冻结或按安全策略回落。模式转换只在一个控制周期边界原子发生，参数组带版本并整组替换。

级联环与实际输出反馈

速度 PID 输出电流请求，电流环/逆变器又有限幅。速度环 anti-windup 应跟踪实际允许的电流请求，而不是自己的软件 clamp；否则下游因母线、温度或过流降额时，上游仍 windup。把 limiter 的 u_applied 反馈到积分回算通道。

死区、摩擦和单向执行器会使正负限制不对称。限幅值可能随电压/温度变化，每周期使用当前限制。限制突变本身会推动积分，需要验证降额与恢复的 bumpless 性。

可复现实验与通过标准

准备支持 C11 的主机编译器、绘图工具、STM32F407 开发板、逻辑分析仪，以及一阶 RC 或带机械保护的低功率电机对象。主机运行数值程序，扫描 Kaw=0、2、8、30，保存 P/I/D/raw/applied。指标包括饱和持续时间、解除饱和恢复时间、超调、切换跳变量和积分峰值。加入测量噪声、Ts ±5% 抖动、速率限制和 NaN 注入。

开发板以 1 kHz 定时器触发控制任务，用 DAC/PWM 驱动一阶 RC 或安全低功率电机平台；GPIO 标记周期，逻辑分析仪验证 deadline。手动输出 0.3，切 AUTO 时设定与测量不相等；在线改增益；强制执行器限幅。

通过标准：anti-windup 相对 kaw=0 显著降低积分峰值和恢复时间且不产生新振荡；manual→auto 输出跳变低于项目阈值；NaN 不到达执行器；周期超限被计数；主机 golden vector 与 MCU 每一步误差在浮点容差内。只看最终 y 曲线不够，必须审计内部状态。

真实故障注入与完整证据链

注入：将 Kaw=0，仅在最终输出 clamp；命令不可达设定值三秒后降回可达值。现象是输出在设定下降后仍卡上限，随后大幅超调。假设包括对象惯性、积分 windup、切换/采样错误。证据是对象时间常数仅 150 ms，而卡限持续远长；I 单调增大；P 已反向但 raw 仍高；Ts 记录稳定。

定位到执行器饱和未反馈积分状态。修复为使用 u_applied-u_raw back-calculation，并让 slew/downstream limiter 返回实际输出；选择 Kaw 后做稳定性扫描。回归覆盖正负饱和、速率限制、manual/auto、在线改参和 NaN，积分有界、恢复时间达标、无额外振荡。链条为：解除限幅后卡死 → 三类假设 → 时间常数/I/raw/Ts 证据 → windup 定位 → tracking 回算修复 → 全限制与模式回归。

调参前先确认执行器和采样模型

若对象有明显延迟、死区或非最小相位，盲目增大 Kp/Ki 会把建模问题变成振荡。先用小信号阶跃识别静态增益、主时间常数、纯延迟和噪声；确定控制周期至少比目标带宽快足够倍数。执行器速率、幅值、死区和下游保护均进入仿真。

调参过程先 P 获得方向和响应，再 I 消除稳态误差，最后在确有需要且测量质量允许时加 D。每次记录闭环指标与裕度，不用“手感不错”批准。参数只适用于识别工况；电机负载、供电和温度变化需做鲁棒性矩阵或增益调度。

anti-windup 也可能调坏

Back-calculation 引入额外反馈极点。Kaw 很大会让 I 对量化/限幅边界快速跳动，出现 chatter；很小则恢复慢。常把 tracking time constant 作为设计参数，再令 Kaw 与其倒数相关，但离散实现仍要检查 Kaw*Ts 尺度。

条件积分在限幅边界附近可能频繁开关，可加滞环或只按“积分增量是否加深饱和”判断。无论哪种方法，记录 raw、applied、I 和 saturation reason。若只记录 applied，就无法区分正常控制和巨大 windup 被 clamp 掩盖。

多个限制器串联时返回最终实际值：amplitude、slew、热降额、电流限制、PWM 最小占空比。每个 limiter 还应给 reason bits，便于确认是谁触发回算。执行器反馈若延迟一个周期，模型和 Kaw 也要按这个延迟验证。

模式状态机与参数热更新

MANUAL 中每周期用实际输出反算 I，更新 y_prev/D；AUTO 入口只切 mode，不突改状态。AUTO→MANUAL 把当前 applied 作为手动初值。FAULT 根据风险快速置安全值或限速回落，并明确是否清积分。恢复不能直接跳 AUTO，应重新验证传感器和跟踪。

参数包整组带版本、CRC 和适用采样周期。在周期边界原子替换。Kp/Kd 改变时，按当前 u_actual-P-D 重算 I 保持输出；Ki 变化不应把已经积累的 I 当作“误差和”重新缩放，除非实现状态定义就是误差和。状态语义必须文档化。

固定点与数值边界

Q31/Q15 需要给每个中间量范围。误差、Kp 乘积、积分累加、微分差分和 back-calculation 相加可能超过最终输出范围；仅最终饱和太晚，内部已回绕。使用更宽累加器、明确右移舍入和每步饱和，并以最大输入序列证明。

量化会形成极限环：误差小于一个码时输出在几个码间跳。死区可减少抖动，却引入稳态误差；dither 可改善平均值但增加噪声。主机 golden model 必须复制 MCU 的定点舍入，而不是用 double 结果直接比较。

浮点不会回绕，却有 NaN/Inf、denormal 和非确定库代价。所有外部参数先检查 finite/range；积分状态每步守门。检测异常后不要继续用上一条可能危险输出，按安全策略处理。

周期抖动与 deadline miss

用 vTaskDelay 启动控制会把执行时间叠加到周期，应该由硬件定时器/ADC 事件触发。记录实际开始时间和完成时间；固定系数实现若 dt 超出允许范围，标记 deadline miss。偶发错过周期时选择跳过更新、使用实测 dt 或安全降级，必须通过模型验证。

D 项对 dt 特别敏感，短周期会放大微分。若使用实测 dt，alpha 也要随 dt 更新；只改除法不改滤波系数不一致。硬实时系统更常保证固定 Ts 并将超限作为故障。

控制计算和执行器更新之间也有延迟。PWM shadow 在下个更新事件生效，等效一个确定延迟；模型中必须包含。优化代码少几个微秒不等于改善，如果相位瓶颈来自整周期更新延迟。

测试 oracle 与发布守门

建立逐样本 golden vector，输入 r、y、mode、limits、参数代次，输出 P/I/D/raw/applied/reason。主机和 MCU 对每步状态比较。覆盖正负零、极值、NaN、饱和进入/退出、速率限制、手自动、参数切换和复位恢复。

闭环指标包括上升/整定、超调、稳态误差、控制能量、饱和占比、积分峰值和切换跳变。安全守门还包括最大输出变化、NaN 拒绝和 deadline miss。任何参数只有在对象不确定性矩阵全部通过后才能发布。

练习题与判断标准

  1. 最终 clamp 是否等于 anti-windup？否，内部 I 仍可能增长。
  2. 饱和时应否冻结所有积分？不一定；帮助退出饱和方向应允许，或用 back-calculation。
  3. manual→auto 如何无扰？令内部 I/D 状态跟踪当前实际输出和测量。
  4. 速度环输出被电流环降额时跟踪哪个量？实际允许/施加的电流请求，而非原始速度 PID 输出。
  5. 实操提交 kaw 扫描、内部状态、切换跳变、NaN/周期守门及 MCU golden-vector 对比；只有一条阶跃曲线判失败。
