🔧 嵌入式知识：I2S/SAI 音频时钟、帧格式与 DMA

工程问题：48 kHz、24 bit 都一样，为什么声音仍然变调并周期爆音

本文锁定平台为 NUCLEO‑H743ZI2 / STM32H743 SAI1 master transmitter + TI PCM3060 DAC slave（software-control mode，经 I²C 配置并读回），48 kHz、立体声、24 位有效样本、两个 32 位 slot、MCLK=256×Fs。控制器依据 ST RM0433 Rev. 8（2023‑01）Chapter 51 SAI，codec 依据 TI PCM3060 SLAS533B Rev. B（2008‑03），I²S 基本时序依据 NXP UM11732 Rev. 3.0（2022‑02‑17）。本次实际执行环境只有 macOS Darwin arm64、Python 3.14.0；没有连接 SAI、codec、DMA、音频分析仪或示波器，因而真实时钟、jitter、波形和模拟音质均为计划验证。

工程现场常说“两端都是 48 kHz、24 bit、I2S”，却仍有四种互不相同的配置可能错：

  • 一秒有多少帧，即 sample/frame rate；
  • 一帧有几个 slot、每个 slot 占多少 BCLK；
  • 24 个有效位相对 WS 边沿从第几个 BCLK 开始；
  • DMA 在内存和 SAI data register 之间一次搬 2、3 还是 4 字节。

任何一个错，线路仍持续翻转，codec 也未必报错。结果可能是幅度翻倍/减半、左右互换、符号错误、速度变调或每隔一个 block 爆音。教程目标不是背寄存器，而是建立一条从 clock tree 到串行 bit、再到 DMA ownership 的可验证因果链。

I²S、SAI、PCM、codec 分别是什么

PCM sample 是某一采样时刻的量化数值；本文用 24 位 two’s complement 有符号整数。I²S 是在 SCK、WS、SD 三根线上传音频字的串行时序；NXP UM11732 Rev. 3.0 §2–§3明确三线、MSB first、two’s complement，并规定 WS 在下一字 MSB 之前一个 clock 改变。SAI 是 STM32 的可编程串行音频外设，能实现 I²S、left/right justified、PCM/TDM 等多种 frame；配置 SAI 不等于已经满足某个 codec 的具体格式。codec 把数字 sample 与模拟电压互换；其中数字重构滤波器先在数字域插值、抑制采样镜像，内部 oversampling（过采样）用更高内部更新率实现该滤波，但不会凭空增加输入 PCM 的信息位。codec 另有 mute、reset、模拟电源和时钟要求。

相邻概念的边界：

  • I²S 规范的基本三线是 SCK/WS/SD；板上常见的 MCLK 是 codec system clock，不应把“有 MCLK”误当 I²S 格式本身的一位。
  • WS 常被叫 LRCLK，本文立体声中一次完整左右 frame 的频率等于 Fs；在 TDM 中 FS 可能只是短脉冲，不能用“左右时钟”解释。
  • SAI 的 slot 是 frame 中固定时隙；一个 slot 可以承载一个 sample，也可以 inactive。sample width 不等于 slot width。
  • master/controller 生成 BCLK/WS；slave/target 接收它们。谁传 SD 与谁生成 clock 是两个维度：master receiver 与 slave transmitter 都合法。

本文沿用器件手册的 master/slave 寄存器术语，同时用 controller/target 解释角色。系统必须有且只有一个被选定的 BCLK/WS controller；两个输出相接会电气争用，两个 target 则没有时钟。

四个时钟的因果关系

本文使用：

Fs 是每声道每秒产生多少新 sample，不是 BCLK。BCLK 为每个 slot 的每一 bit 提供节拍；24 位 sample 放进 32 位 slot 时仍要发送 64 个 BCLK/frame，所以 48 kHz × 2 × 24 = 2.304 MHz 是错误公式。MCLK 驱动 PCM3060 内部过采样与数字滤波；它和 Fs 的合法整数比由 codec 数据手册限定。SAI kernel clock 是 STM32 RCC 提供给 SAI 分频器的源。

RM0433 Rev. 8 §51.4.8 在 NOMCK=0 时给出：

取 MCKDIV=8、OSR=0、FRL+1=64，得到 MCLK=12.288 MHz、FS=48 kHz、BCLK=3.072 MHz。该节同时要求生成 MCLK 时 frame length 为 8–256 的 2 次幂。主机 lab 将错误的 48-bit frame 先拒绝为 AUDIO_MCLK_FRAME_NOT_POWER_OF_TWO；这不是说所有 SAI 模式都禁止 48 bit，而是本文 NOMCK=0 窄化配置的硬件条件。

PCM3060 SLAS533B 的 “SYSTEM CLOCK”/Table 2 规定 DAC 可接受 128/192/256/384/512/768×Fs，48 kHz 下 256× 就是 12.288 MHz；“PCM AUDIO INTERFACE”说明 slave mode 的 BCK 必须是 64×Fs 或 48×Fs，见 PCM3060 Rev. B 官方 datasheet。因此本文 64-bit frame 同时满足 MCU 与 codec；只算出整数分频还不够，必须与 codec 的合法 ratio 表交集。

主机 oracle 明确分成两层。check_format()/check_clock() 是 generic arithmetic：只检查数值能否装入抽象 slot、时钟公式能否闭合，允许许多并非本文硬件组合的输入，用来演示诸如 48-bit frame 在该 SAI MCLK 公式下为何失败。正式启动只能经过 check_stm32h743_pcm3060_format() 和 check_stm32h743_pcm3060_clock()：本文冻结配置只接受 Fs=48 kHz、stereo 2×32 slot、24-bit sample、I²S 或 LEFT、MCLK/Fs=256。奇数 slot、64-bit slot 与 PCM3060 不支持的 32-bit audio word 即使 generic 算术可算，也分别以平台错误拒绝。这个窄化不是说 PCM3060 数据手册中的其他合法模式不存在，而是说未进入本文 register、DMA 与实测证据闭环的组合不能借 generic PASS 获得平台认证。

ppm、相位噪声和 jitter 不是同一个误差

ppm 频率误差描述长期平均频率偏离；它影响 pitch、与另一时钟域之间的 buffer 漂移。jitter 描述边沿相对理想位置的短期时间波动；它会压缩 setup/hold margin，并在 DAC 中把采样时刻噪声转换成幅相误差。相位噪声是在频域描述 oscillator/PLL 的随机相位扰动。PLL（phase-locked loop，锁相环）比较参考时钟与反馈相位，再通过闭环控制合成目标频率；分频算术精确并不自动消除参考噪声、环路噪声或电源耦合。因此 PLL 配成“精确 12.288 MHz”只解决名义频率，不证明 jitter 合格。

板级验收要在 MCLK/BCLK/WS 上分别测频率、duty cycle（一个周期内高电平所占比例）和周期 jitter；示波器带宽、探头负载和统计窗口也要记录。PCM3060 Figure 21 给 SCKI cycle/high/low/duty 要求，Figures 24–25 给 BCK/LRCK/DIN setup/hold：数据必须在采样边到来前至少稳定 setup 时间，并在边沿后继续稳定 hold 时间。STM32 的 CKSTR 选择采样边；边选反、板级延迟过大或 jitter 吃掉 margin 时，逻辑分析仪仍可能“能解码”，codec 却已违反保证条件。

I²S 与 left-justified 只差一位，却不是近似格式

UM11732 §3.1–§3.2 规定 I²S：WS 改变后，下一字 MSB 在一个 SCK 周期之后出现；WS=0 为左、WS=1 为右。left‑justified 则通常让 MSB 与 channel 边界紧邻、没有这一位延迟。right‑justified 把 LSB 对齐 slot 末端。三者都可传 24 位，但 bit 位置不同。

若 transmitter 发 left‑justified、receiver 按 I²S 从 offset 1 取 24 位，特定正数 0x200000 会被读为 0x400000，即乘二；负数可能左移、回绕为另一个 two’s complement 值。这个症状不是固定“音量变两倍”：接近满量程会改变符号或削顶，波形内容决定听感。最可靠的格式探针不是音乐，而是正/负 full-scale（24 位可表示的最大/最小幅值）边界、每次仅置一个有效 bit 的 walking-one、左右不同常量和逐 sample 单调变化的 ramp；这些 pattern 能把符号、位移、左右顺序和丢帧分别显露出来。

ST SAI 把 frame 与 slot 分开配置。RM0433 §51.4.5–§51.4.7 定义 data size、FS shape、slot size、first bit offset 和 active slots，并给出语义约束：

DMA ping-pong 的目的不是“更快”，而是给 deadline 一个边界

持续音频不能等整个文件处理完再发送。ping‑pong/double buffer 让 DMA 播放 A 时 CPU 填 B，到 block boundary 交换。ownership 为：

PUBLISHED 表示内容与 cache 可见性已经冻结、等待下一个边界，虽然 DMA 尚未开始读，也不再属于 CPU。本文选择 cpu_commit() 原子地把 CPU_WRITABLE 转成 PUBLISHED；commit 后的 cpu_mutate() 必须失败，不能保留“ready=true”同时允许写。主机 hostile 明确执行 commit → mutate（拒绝）→ boundary（仍使用未被篡改的已发布块）。目标实现中 clean 和 release barrier 必须先完成，最后一个原子 owner store 才是发布点。

每 block N 个 frame 的硬 deadline：

本文 N=128：Tblock=2.666667 ms，每 block 1024 byte，双 buffer 2048 byte，边界事件 375 次/s。准入条件是严格不等式 Tprocess_worst < Tblock：等号代表零调度/时钟/测量余量，必须与超时一样拒绝。主机用 Tblock−0.001 µs、Tblock、Tblock+0.001 µs 三点锁住这个边界；前一点只证明比较符号正确，并不代表 1 ns 工程余量足够。实际 CPU 的最坏处理、调度、cache clean、总线等待和发布总和还要小于扣除项目 margin 后的预算；平均 0.4 ms 没有意义。增大到 256 frame 把 deadline 变 5.333 ms，却也增加至少一个 block 级别的排队延迟和内存。

若 D‑cache 开启，TX block 由 CPU 写后需在 DMA 读前 clean；RX block 由 DMA 写后 CPU 读前 invalidate，且 buffer 应独占 cache line，因为按地址维护通常会扩展到整条 line，共享 line 会把无关对象的 dirty 写回或失效一起卷入。DMA complete 归还的是内存块，不表示 SAI/codec 模拟输出已经播放；外设 FIFO、serial frame、codec digital filter 与 analog path 继续引入延迟。

FIFO threshold、underrun 与 overrun 的含义

FIFO 吸收很短的总线抖动，不替代 block deadline。RM0433 §51.4.9 定义 8-word FIFO 和按方向/threshold 产生的 FREQ/DMA request；TX threshold 过低会缩短补充余量，过高会增加突发请求。DMA width 和 burst 必须与一个 FIFO word/slot 的合同一致。

underrun 是 transmitter 需要下一个 slot 时 FIFO 空；RM0433 §51.4.14 规定设置 OVRUDR，并发送 MUTE/zero 直到能在正确 slot 恢复，从而避免内存指针与 slot 永久错位。听到的是 click、短静音或周期噪声，不能仅归因 codec 音质。overrun 是 receiver FIFO 满时新数据到达，数据被丢弃并置同类错误标志。两者都意味着连续流已经有 gap；清 flag 后继续不等于上层时间线完整。

故障 ISR 应冻结最近若干 block 的 trace：DMA half/full 时间、owner、FIFO level、OVRUDR、处理时长、cache 操作和 sample sequence。日志通过低速 UART 同步打印可能反过来制造 underrun；用 RAM ring 记录，停止后导出。

启动、停止和采样率切换是状态机

PCM3060 默认 ADC/DAC 为 slave；其 “POWER-ON RESET AND EXTERNAL RESET SEQUENCE” 规定内部 reset 释放与 1024 个 SCKI 有关，随后还有以 Fs 计的 fade-in 延迟；若 SCKI/BCK/LRCK 不同步，器件保持 reset/power-down 或重新同步。数字寄存器写成功不等于模拟输出已稳定。

安全启动流程：

RM0433 §51.4.3 说明 master TX 使能后会产生 bit clock，FS/数据行为受 FIFO 内容影响；预填 FIFO/DMA 可以避免第一帧 underrun。§51.4.16 给 DMA 配置顺序：先配 SAI/FIFO，再配并启用 DMA，最后启用 SAI。

停止不能先拆 clock：RM0433 §51.4.15 规定清 SAIEN 后，已经开始的 frame 会完成，SAIEN 保持高直到真正停下；同步的两个 subblock 要按手册顺序停。项目流程应 soft mute、停止生产新 block、等最后 frame、禁 SAI 并读回、停 DMA/flush、再按 codec power-down/fade 关闭 clocks。

采样率切换不是在线改一个 divider。安全序列是 mute → drain/停流 → 禁 SAI/DMA → codec 进入允许改 clock 的状态 → 重配 PLL/MCKDIV/frame/codec ratio → 等锁定与同步 → 清 FIFO/error → 预填 → 启流 → fade/unmute。每次格式切换都递增 format_generation（格式代次）；block 和回调携带创建它们时的代次，旧 rate 的迟到回调与当前代次不符就必须拒绝，避免把 44.1 kHz/旧 slot 布局的数据发布到 48 kHz 新流。

同步时钟域与异步时钟域

本文 playback 中 STM32 同时生成 MCLK/BCLK/WS，PCM3060 DAC 为 slave，所以数字流共享一个 rate 来源，不存在 MCU→DAC 的长期相对采样漂移。PCM3060 仍支持 ADC 与 DAC 用 SCKI1/SCKI2 完全异步；若把一个独立 ADC 时钟域的数据直接放进另一个独立 DAC 时钟域，有限 ring 最终必满或必空。

相对频差 Δppm 的一阶累计：

spare_frames 是沿当前漂移方向从工作水位到空/满边界的容量，不是 ring 总容量。endpoint margin 为指针量化、满空判定和不可触碰端点预留；runtime margin 覆盖监测发现偏移后到 ASRC/控制动作真正生效期间仍会累积的漂移与调度 jitter。零 residual 只表示数学上恰好撞到边界，没有安全余量，必须拒绝。主机以 drift=288、endpoint=8、runtime=16 构造 required=312：capacity 311 失败、312 以 zero-margin 失败、313 才剩 1 frame。

48 kHz、100 ppm、60 s 是 288 sample；128-frame spare 不到一分钟就耗尽。加大 ring 只推迟故障并增加 latency，不能修复平均 rate。解法是共享低 jitter clock，或使用 ASRC（asynchronous sample-rate converter，异步采样率转换器）/自适应 resampler：根据两个独立 rate 与 buffer level，插值出目标时钟域的新 sample，使长期输入/输出数量守恒。它会引入滤波延迟、算力和幅频/噪声指标，不能仅凭“FIFO 不空”验收。丢/重复一个 sample 是粗暴 rate matching，会产生相位不连续，只有业务明确允许时才可用。

clock domain crossing（CDC，跨时钟域）还涉及控制信号：接收域若直接采样正在变化的多 bit 二进制 write pointer，可能把不同时刻的各 bit 拼成不存在的值。异步 FIFO 通常把 pointer 编成相邻计数只改变一位的 Gray code，再让每一位经过多级触发器 synchronizer 降低亚稳态传播概率；Gray code 不消灭亚稳态，也不能替代满/空边界证明。本文 MCU 内存 ring 不声称替代硬件 CDC；若 SAI 是 external-clock slave，DMA/CPU 看见的是同步后的外设请求，仍需对 clock loss 和 frame error 做恢复。

延迟预算与音质证据

端到端 latency 不是 N/Fs 一个量：

group delay 是滤波器不同频率分量的相位延迟换算，不等于 CPU 执行时间。codec 数字滤波可能让 sample 在接口出现与模拟波形出现之间相隔多个采样周期。loopback 测试要把数字时间戳与模拟脉冲对齐，不能把 GPIO callback 当声学输出时刻。

音质验收至少包括 frequency/pitch、THD+N、noise floor、channel separation、full-scale、DC offset、启动/停止 pop，以及 underrun count。THD+N 是基波以外的谐波与噪声相对基波的合成量；noise floor 是无目标信号时的残余噪声谱；channel separation 衡量只激励一个声道时串入另一声道的程度；DC offset 是输出平均值偏离目标零点的直流分量。它们依赖带宽、加权、负载、幅度和测量链，必须连同这些条件给阈值。逻辑分析仪证明 bit 正确，却不能证明模拟电源、参考、输出重构和负载正确；音频分析仪证明一条 sine 好看，也不能证明所有格式/错误恢复。

目标硬件可复现实验（计划验证，本次未执行）

准备 NUCLEO‑H743ZI2、PCM3060 板、独立干净的 3.3/5 V 电源、四通道以上逻辑分析仪/示波器、音频分析仪或经校准 ADC。探测 MCLK、BCLK、LRCK、DIN 与 ISR GPIO；记录 RCC/SAI/codec register dump、DMA owner/sequence、OVRUDR。

步骤：

  1. 正常配置 48 kHz/2×32/24-bit I²S，发送 [+FS, 0, −FS, walking-one] 与左右不同 ramp；解码每个 bit 位置。
  2. 保持 PCM3060 DAC 的 FMT2[1:0]=00（I²S），故意把 STM32 SAI TX 改为 left‑justified；验证 0x200000 在这一方向的具体左移，并覆盖负值/边界，不能只听音乐。另做反向配置时要单独推导：I²S transmitter 被 left‑justified receiver 解释会向另一方向错位，不得套用本实验的 gain_x=2。
  3. 当前正式 validator 只允许本文 48 kHz/2×32/24-bit/I²S-or-LEFT/MCLK=256× 配置；先注入奇数 slot、64-bit slot 和 32-bit codec word，必须在启动前拒绝。44.1/96 kHz 仅作为后续扩展候选：分别补齐 kernel clock、PCM3060 ratio 与实测 generation 后才能进入正式 validator，不能复用 generic 算术 PASS。
  4. N=32/64/128/256，注入 CPU 负载和总线争用；统计处理 worst case、FIFO level、underrun/overrun 与模拟 click。对每个 N 验证 Tprocess_worst + project_margin < Tblock，等号必须失败。
  5. 故意执行 fill/clean/commit 后再写 PUBLISHED block，以及写 active DMA block、遗漏 cache clean；前两种 ownership 守门必须拒绝，遗漏 clean 要由线路 pattern/CRC/error 捕获。恢复后从静音 frame boundary 重启。
  6. 在异步 ADC→DAC 实验中给两个 clock 注入已知 ppm 差，验证 ring slope；容量验收必须扣除 endpoint 与 runtime margin 且 residual 严格大于零，再启用 ASRC/共享 clock 对照。
  7. 覆盖 power-on、reset、mute、stop、rate switch、clock loss/recovery，测 codec fade 与首末帧。

通过标准：只有平台 validator 接受的 generation 才能启动；48 kHz、3.072 MHz、12.288 MHz 均在项目 ppm/jitter/duty 范围；bit/WS/edge 与 UM11732、PCM3060 Figures 24–26 一致；DMA words 与线路 samples 逐项相等；commit 后 block 不可写；Tprocess_worst + margin < Tblock 且 elastic residual > 0；所有 deadline miss 都置 OVRUDR/项目错误且不静默；正常压力矩阵零 underrun；启动/切换 pop、THD+N 等达到产品阈值。未给阈值或只凭听感不通过。

故障注入与完整定位闭环

注入：保持 PCM3060 DAC slave 的 FMT2[1:0]=00（I²S），却把 STM32 SAI master TX 配成 left‑justified，也就是在 WS 边界立即发送 MSB。现象预测：低幅正弦在这一错位方向可表现为约两倍幅度，接近满量程则发生符号翻转或削顶；左右 frame rate 和三个 clock 仍可能全部正确。假设包括 codec 数字衰减/模拟增益、软件饱和或 sign extend、串行 bit alignment。

证据计划：先读回 PCM3060 Register 67 的 FMT2[1:0]=00 以及数字衰减/mute 配置，排除 codec 自身增益设置；再保存 STM32 SAI frame/slot register dump，并用逻辑分析仪确认 SD 的 MSB 与 WS edge 同时出现，而 I²S 要求晚一个 SCK；最后用 0x200000、walking‑one 和左右不同常量驱动 DAC，以音频分析仪或经校准 ADC 测模拟输出，和主机 oracle 预测的 0x400000 对照。PCM3060 DAC 不提供“已解码 sample 的内存 raw”，所以本文不把不存在的读回通道列作证据。上述证据共同把故障定位到 format mismatch，而不是笼统的“24-bit 不兼容”。修复为两端都选 I²S，并锁定 frame/slot/offset/polarity generation；重新预填、静音重启。回归覆盖正负边界、walking-one、左右不同 ramp、所有支持 Fs 和 reset/rate switch。

闭环：幅度异常/削顶 → 增益、软件数值与 format 三假设 → 两端 register + WS/BCLK/SD 波形 + 模拟探针 → TX 提前一位 → 双端同代 I²S 格式 → 全 pattern 与模拟指标回归。目标波形和模拟测量本次未执行，因此这里是计划闭环，不是伪造实验。

另一个独立故障是 CPU 处理 2.800 ms 超过 128-frame 的 2.667 ms deadline。主机 lab 已证明合同会拒绝；目标板上仍要以 OVRUDR、FIFO 与音频波形确认真实 underrun，不能从主机算术直接宣称硬件爆音。

练习题与可判定答案

  1. 48 kHz、立体声、24-bit sample 为何本文 BCLK 是 3.072 MHz？ 因两个 32-bit slot：48000×2×32。答 2.304 MHz 判错。
  2. I²S 与 left-justified 的核心位置差异？ I²S MSB 在 WS 改变一个 SCK 后，left MSB 紧邻边界；必须提“一位”，只答极性不同判错。
  3. 0x00E00000 作为 24-bit sample 是多少？ −0x200000，需要显式 24→32 sign extension。
  4. DMA half/full callback 是否证明声音已从模拟端输出？ 否；只归还内存区，后面仍有 FIFO、serial、codec filter/analog delay。
  5. 128-frame buffer、48 kHz 的 refill deadline？ 2.666667 ms，但通过条件是 worst-case 严格小于它；恰好相等因零 margin 判失败。
  6. cpu_commit() 后、boundary 前还能改 block 吗？ 不能；它已从 CPU_WRITABLE 原子转为 PUBLISHED/DMA_READ_ONLY，否则 clean 后内容和 DMA 将读内容不一致。
  7. 100 ppm 异步 clock 用更大 ring 能永久解决吗？ 不能；只推迟耗尽，需共享 clock 或 rate conversion。容量还必须扣 endpoint/runtime margin，residual=0 不通过。
  8. generic check_format() 接受 64-bit slot 能否证明本文平台支持？ 不能；正式路径还须通过 STM32H743+PCM3060 validator，本文只认证 48 kHz、2×32、24-bit、I²S/LEFT、MCLK=256×。
  9. 实操验收提交 clock 实测、UM11732 对齐波形、walking-one 解码、DMA owner/commit/deadline trace、elastic margin、OVRUDR、启动/切换与模拟指标。只提交一段“听起来正常”的录音不通过。
