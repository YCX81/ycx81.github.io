🔧 嵌入式知识：嵌入式威胁建模与攻击面

从产品资产而不是漏洞清单开始

本文以计划中的 STM32U575 工业振动节点为具体对象：MCU 运行安全启动与 OTA，外接 QSPI Flash，BLE 用于现场维护，RS-485 接 PLC，SWD 与 UART 只应在制造/维修阶段开放，云端管理设备证书与更新。目标板、射频、调试器和云服务本次均未使用；本次已执行证据仅是 macOS Darwin arm64、Python 3.14.0 的确定性威胁模型 oracle，不能证明芯片安全状态、无线协议栈或产品渗透测试结果。

资产是需要保护且损失会造成业务后果的对象，包括固件完整性、设备私钥、传感数据真实性、执行器授权、可用性和安全日志。威胁是某主体利用条件使资产受损的可能路径；漏洞是路径中的可利用弱点；风险是后果与发生可能性的决策表达。攻击面是攻击者可与系统交互或影响系统的入口、状态与生命周期过程，不等于 TCP 端口数量。暴露的 SWD、恢复按键、工厂命令、二维码、外部 Flash、无线配对、解析器、供应链构建、退役设备都属于攻击面。

OWASP Threat Modeling Project提出“我们在构建什么、哪里可能出错、如何处置、是否做得足够好”的循环。它强调模型服务于设计，而 STRIDE 只是提醒 spoofing、tampering、repudiation、information disclosure、denial of service、elevation of privilege 六类问题的助记法，不会自动给出风险等级。STRIDE 与 attack tree 相邻：前者按威胁性质提示遗漏，后者从攻击目标向所需步骤分解 AND/OR 路径；与 FMEA 的差别是攻击者具有意图、会适应防御，失效概率表不能替代对抗分析。

数据流、信任边界和主体

Data-flow diagram 的节点至少区分 process、store、external entity 和 asset，边说明协议、方向、身份、权限和数据。Trust boundary 是一侧的身份或控制假设不能直接延伸到另一侧的位置，例如 BLE 无线到设备、普通世界到 TrustZone 安全世界、工厂站到 HSM、设备到云。加密通道不消除边界：TLS 能保护传输机密性与完整性，但端点授权、证书生命周期、解析器和已解密数据仍可能失败。

主体是能发起动作的身份，如设备、维修员、租户服务或工厂站；身份认证回答“是谁”，授权回答“允许做什么”，审计回答“后来如何证明做过什么”。把“已登录”当管理员授权会越权。安全域是隔离执行和数据的机制边界，TrustZone、MPU、进程和容器的保证不同；隔离只有在启动配置、内存属性、DMA、异常入口和调用参数全部正确时成立。

生命周期与成立条件

NISTIR 8259 Rev.1面向 IoT 制造商的基础网络安全活动，要求先理解客户与风险，再定义能力、沟通和支持；NISTIR 8259A给出设备识别、配置、数据保护、接口逻辑访问、软件更新、状态感知等核心能力。它们是通用基线，不替代工业 IEC 62443、医疗或汽车强制要求。能力存在也不表示正确实现，例如“支持更新”若不验证签名、允许回滚或更新失败变砖，反而扩大攻击面。

威胁模型要覆盖设计、制造、运输、首次 claim、正常运行、维修、所有权转移和退役。制造时 SWD 合法，出厂后同一入口可能成为提权路径；维修解锁需要时间窗、授权、审计和重新锁定。退役若只删除云记录而设备仍保存租户证书，会泄露资产。Assumption 是推理公理，如“攻击者可物理接触 10 分钟但不能开封安全元件”；必须有范围、依据、负责人和失效时的处置。把假设藏在备注里会让风险数字伪精确。

Attack path 需要从 entry 沿可达状态到 asset。缓解措施应打断路径中的明确条件：安全启动阻止未授权镜像，不阻止合法旧镜像回滚；接口认证阻止匿名命令，不阻止被盗维修凭据；rate limit 减少在线猜测，不阻止射频干扰。Defense in depth 指独立失效模式的多层控制，不是同一库函数调用两遍。若两个“独立”检查共享同一可篡改配置，它们是共同原因。

风险处置与验证证据

Risk treatment 有 avoid、mitigate、transfer、accept。Accept 不是“暂时不修”，而是授权角色基于残余后果、假设和监测做出的有时限决定。Residual risk 是实施控制后仍存在的风险；必须记录未覆盖路径和复审触发器。严重度和可能性常是有序等级，不宜相乘冒充物理概率。优先级还要考虑攻击前置条件、可扩展性、检测机会、供应链传播和安全后果。

控制与 verification 要绑定。安全启动用负向签名、版本回滚、掉电和 key revocation 测试；调试锁用上电、低功耗唤醒、故障注入和量产读回检查；解析器用 fuzz/sanitizer 与目标机回放；权限用跨租户、过期凭据和并发撤销测试。测试环境必须绑定固件、芯片生命周期位和配置摘要。扫描器“0 个高危”只表示其规则和可见面未发现，不是攻击面闭合。

PSA Certified Platform Threat Model and Security Goals给出平台资产、攻击者能力、范围排除与安全目标的参考边界，但只有采用其假设和实现要求时才可映射；本文 STM32U5 计划仍需检查 ST 的具体 TrustZone、RDP 与 debug authentication 实现，不能从参考模型推导芯片已安全。

本次已执行的可复现实验

staging/deep_batch_am/threat_surface_lab.py 用 exact node kind/trust/version、带认证和加密布尔值的数据流，以及 threat 的 asset、entry、STRIDE、assumption、mitigation、verification、residual 字段建立模型。统一状态验证器要求 threat.asset 真正指向 kind=ASSET 的节点，并令 threat ID 在整个模型唯一；load、live gate、publish 与 restore 共用该域，不能让内存里的坏状态绕过恢复门。发布门还要求每个 UNTRUSTED entry 至少被一个威胁覆盖，且每条 threat 的 entry 必须沿实际有向 flow 可达其 asset；verification/residual 不得为 NONE/UNKNOWN。

revision 在 live load 时必须是 exact non-bool successor，但持久状态可以是任意大于零、已完整发布的合法 revision；restore 不伪造一次“从零到当前”的 load，而是验证 revision 2 的完整状态与 publication digest 后直接安装。因此 fresh 进程可精确恢复 revision 2，重复 ID、非资产 target、publication 篡改在各入口均原子拒绝。所有失败前后 snapshot byte-identical，64 KiB 是包含 publication 的整个持久域上限。

计划中的目标板故障注入实验

准备：STM32U575 样机、隔离 SWD、BLE sniffer、可控 OTA 服务、电源毛刺设备和冻结固件；先记录安全生命周期、option bytes、固件与模型 revision。步骤：正常签名更新建立基线；分别注入错误签名、合法旧版本、更新写入中掉电、未授权 BLE 命令、重放维修 token、复位期间 SWD 连接和高频请求。观测 boot reason、debug 状态、认证判决、写入分区、速率限制与安全日志。通过标准：任何未授权镜像都不执行，旧版本按 anti-rollback 拒绝，掉电回到已认证槽，跨租户命令无副作用，日志绑定版本且过载不绕过授权。

故障闭环：现象是“BLE 命令已认证”却能在设备 claim 前执行擦除。假设是默认工厂角色过宽、状态机缺 owner 条件或解析器混淆命令。证据显示签名有效，但 authorization 只检查厂商 key，未检查 lifecycle=CLAIMED。定位为认证与授权混淆。修复为命令策略同时绑定主体、lifecycle、操作和 nonce；回归覆盖未 claim、已 claim、转移中、过期 token、重放、掉电恢复和撤销窗口，并更新 attack path 与 residual risk。

练习与验收答案

  1. TLS 是否移除无线信任边界？否；它保护通道，端点授权、解析和 DoS 仍跨边界。
  2. STRIDE 数量能否作为风险分数？不能；类别数不代表后果或可行性。
  3. 关闭端口是否等于缩小全部攻击面？否；物理、供应链、恢复和生命周期入口仍在。
  4. 机器验收：删除 untrusted-entry coverage、verification/residual 门、exact revision、publication binding 或失败原子性之一，相应 hostile/pseudo-state 必须失败。

物理攻击、供应链与资源耗尽的边界

Remote、adjacent、local 与 physical attacker 的能力不同。物理可达并不自动等于能解封装读 key，但可接触测试点、替换 Flash、控制电源和时钟；模型应列出时间、工具、是否可破坏性开封和攻击是否需隐蔽。Fault injection 用电压、时钟、光或电磁扰动改变执行，不等于普通软件输入 fuzz；防护要用冗余检查、控制流完整性、传感器和失败安全状态，并在目标芯片上测试。侧信道从功耗、时序或电磁泄露秘密，常数时间软件只处理部分时序路径，不覆盖缓存、总线或模拟泄露。

Supply-chain threat 包括构建机、依赖、签名服务、代工测试脚本、器件替换和物流。SBOM 说明组成，不证明组成可信；reproducible build 帮助比较产物，不证明源代码无后门；code signing 证明授权 key 签过字节，不证明签名者判断正确。需要把 source review、依赖来源、构建隔离、artifact provenance、签名授权和入厂检查连成证据链。第三方 blob 无源码时，必须记录更新责任、接口权限和失效隔离。

DoS 在嵌入式中常先耗尽 RAM、Flash endurance、battery、radio airtime、任务时间或 watchdog budget。Rate limit 需要按身份和资源分层；全局限流可能让一个攻击者饿死所有租户。失败日志本身也可写爆 Flash，因此要有 bounded ring、聚合、远端导出与关键事件保留策略。Watchdog 只能从死锁复位；若攻击请求每次都在 deadline 内完成却持续占满 CPU，它不会触发。安全控制必须进入 worst-case execution、队列和能量预算。

Privacy threat 也不是“已加密”就结束。稳定 BLE 地址、证书 subject、流量长度和更新时间可形成跟踪；调试日志可能包含 token、位置和传感原始数据。Data minimization 要说明采集目的、保留时间、访问和删除，设备 factory reset、所有权转移与云备份的删除语义要一致。匿名化若仍有稳定组合特征可能被重新识别。

模型维护触发器包括新接口、固件/bootloader、芯片 revision、云权限、制造流程、漏洞情报、现场异常和假设失效。Diff 不能只比较 threat 行数；要比较资产、边界、flow、版本与 verification。每个 accepted residual risk 应有到期日和 owner。模型若无法回答“哪一版产品、哪个模式、什么攻击能力、哪条证据”，就不能支持发布决策。

📖 IELTS Academic 新词（4 个）

本组按 AWL 高频子表推进，并刻意打散相同首字母，避免相似词互相干扰。

🔊 跟读

# Word 音标 核心义 词族
1 compute /kәm’pju:t/ 计算 computed, computing, computes
2 depress /di’pres/ 使降低；使沮丧 depressed, depresses, depressing
3 link /liŋk/ 联系；连接 linked, links, linking
4 secure /si’kjuә/ 安全的；获得；确保 secured, securing, secures

搭配与语境

  • compute · compute a value / computing resources
    • The model computes the likely cost under several scenarios.
  • depress · depress wages / depressed demand
    • High interest rates may depress investment in new housing.
  • link · a link between / closely linked
    • Research shows a strong link between poverty and poor health.
  • secure · secure funding / ensure secure access
    • The organisation secured funding for a three-year project.

  • link — a relationship between things; to connect them
